# Tasks

Use the [design](design.md) for migration and removal ordering and the [delta specs](specs/) for command contracts. Keep the build and tests passing after each task. Develop and verify the new modules behind the existing CLI until the coordinated cutover in group 5; do not ship two workspace modes. Run focused tests on Node 24 and use disposable local Git repositories for stateful scenarios.

## 1. Checkout identity and provisioning

- [x] 1.1 Build shared inspection for canonical workspace and checkout paths, actual Git top-level and Git directory, root tracking, legacy artifacts (including retained data without a checkout), and exact origin matching after Git fetch URL rewriting. Verify that a matching manual clone is accepted and that a linked worktree, symlink escape, foreign checkout, reused alias, and inaccessible path are not mistaken for eligible or missing sources.
- [x] 1.2 Build the former-source lookup used by removal and doctor from the declaration immediately preceding removal in root HEAD history. Verify current declarations win, ambiguous or shallow history does not establish ownership, and an undeclared directory without matching origin evidence is preserved.
- [x] 1.3 Implement `clone` selection and provisioning, including manifest-only `--list`, terminal selection, baseline/default branch, declared remotes, temporary checkout publication without clobbering, and per-alias failures. Verify with local remotes that an existing valid clone is left unchanged, a failed clone leaves no usable partial checkout, and one failed alias does not prevent other eligible clones. Verify alias-specific ignore coverage, conflicts with user rules, and continued visibility of `oms/` agent instruction files.

## 2. Local checkout removal

- [x] 2.1 Build removal planning for explicit aliases and `--all`, including verified former sources and separate reporting of unidentified paths. Verify that a blocked selected checkout prevents all deletions, that declining or omitting required authorization is write-free, and that an already absent declared checkout is a no-op.
- [x] 2.2 Implement recoverability checks against current origin refs without changing source refs or files. Verify that a merged branch with no same-name remote branch passes, mismatched or missing tags block, detached HEAD and reflog-only commits are checked, and stale refs do not substitute for proof. Verify the plan names the local branches and tags that would be lost.
- [x] 2.3 Implement the inaccessible-origin exception and deletion guards. Verify a single explicitly named checkout needs a separate exact-alias response, `--all` and unattended use cannot take the exception, and neither `--yes` nor `--force` supplies that response. Cover a branch with no upstream, a branch ahead of its last known origin upstream, unverifiable reflog-only history, stash, in-progress Git operations, and managed or external linked worktrees. Verify `--force` affects working files only.
- [x] 2.4 Apply only the approved removal plan, rechecking each target before deletion. Verify a changed remaining target stops the batch and reports completed and unattempted removals; successful removal preserves the manifest, root index and history, ignore rules, and remote state. Document selection, safeguards, and exception recovery in the command guide in this group.
